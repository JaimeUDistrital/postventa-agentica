# T03 · Herramientas del agente + adaptadores mock — HECHA (intentos: 1)

Prueba: `npx vitest run src/core/tools src/core/adapters && npx tsc --noEmit` → 2 archivos, 29 tests verdes; tsc sin errores.

## API exportada
- `@/core/adapters/mock`: `createMockPorts(fixtures, { now? }): Ports` (now por defecto DEMO_NOW; fija `holdHasta`). `test-fixtures.ts` = datos mínimos solo para tests.
- `@/core/tools`: `executeTool(name, args, ctx)`, `estimarKm(vehicle, now)`, `parseQuoteId(id)`, `encodeQuoteId`, y las 5 funciones por nombre.
- Archivos internos: dates.ts, estimador.ts, run.ts (validación Zod + traza), quote.ts, handlers.ts.

## Decisiones
- El puerto `hold` no recibe `holdHasta`: el mock lo calcula con su reloj (`now`) y la herramienta lo reescribe en la salida como ctx.now + policy.holdReservaMinutos (en reintentos idempotentes devuelve la reserva previa tal cual). Sugerencia opcional de contrato: añadir `holdHasta` al input de `hold`.
- quoteId = `q_${vehicleId}_${hitoKm}_${extras.join("+")}_${descuento}`; limitación: vehicleId sin segmento numérico de 4+ dígitos.
- tool_call con latencyMs 0; tool_result con la latencia del sistema (CRM 120, Inventario 180, Tarifario 90, Taller 220, Aseguradoras 350). verificar_stock emite 2 tool_result (Inventario y Tarifario).
- sin_stock/requiere_confirmacion/sin_disponibilidad son ok:true (salida válida); descuento fuera de política, entrada inválida y errores son ok:false.
- Cada llamada reserva `repuestosApartados` = skus de la cotización (no descuenta stock en el mock).
- Franja con slotId ocupado o sin franjas libres → estado "sin_disponibilidad" con alternativas valle.
- Casos: HC-<8 hex>, creadoEn = new Date().toISOString().
